# Issue #13 / #16: Component engine decision — 2026-10-25

Decision: **jsco**. jsco passes the required tested browser subset and has the fastest eligible complete cold start. It becomes the default; Jco is retained as an explicit baseline. Polyengine remains experimental because Unicode argv traps.

Production benchmark source: `da7a02adcf8070723d90a652ad659b1f7775dd69` (dirty: false). All three engines are in the same build. Chromium 154.0.8037.57, Node v24.19.0, Playwright 1.56.1, INTEL(R) XEON(R) PLATINUM 8573C, linux/x64 6.18.55.
Component SHA-256: `f616d0be00c46e6d467d65e0fb40717c0f138a2bcae9e90db6b321151ac98ab8`. wasi-sdk 27.0; flags: -O2 -Wall -Wextra -Werror -Wl,--strip-all.

All 30 trials per engine are independent browser processes/contexts/pages/Workers. Order rotates by trial block; there is no parallel measurement and no build/test runs alongside the final comparison. Fixture preparation and page/browser startup are outside `startupMs`; Worker construction through page receipt of READY includes runtime loading, translation/parse, host linking and instantiation. OPFS is cleared and miss/disabled is asserted. OS page caches are not flushed. No samples or outliers are removed.

The selection requires >=5% improvement and a bootstrap interval lower bound >0, plus compatibility. The interval uses 10,000 independent median resamples, seed `0x5341`. A 50% reduction is an effort target; the measured jsco reduction exceeds it. Polyengine speed does not override its compatibility failure.

## Compatibility and stability

| Engine | Development | Production | Eligibility |
| --- | --- | --- | --- |
| Jco | 127 initial passes; two Vite reload interruptions; both targeted reruns pass | 13/13 pass | Baseline |
| polyengine | Focused P2 suite: 6/7 pass | 11/12 pass | Fail: Unicode argv |
| jsco | 128/128 pass | 12/12 pass | Pass |

The raw initial Jco report, navigation interruptions and targeted rerun are retained. File changes during concurrent correctness builds triggered development-server reloads; the two affected tests pass with file updates stopped. They are not startup benchmark trials and no performance samples were discarded.

Coverage includes stdio separation, 1 MiB mixed P1/P2 pipelines, file namespaces/locks, exit codes, traps/stops, pollable and stream lifetime management, generated walos process/IPC/terminal bindings, owned stream transfer and real Worker lifecycle/READY failure races. Engine-specific tests cover polyengine plan miss→hit, reload→hit, corruption→regeneration, post-READY saving/failure and jsco without cache artifacts/hash spans. The one Jco-specific application-cache test is excluded for candidates; explicit Jco cache tests remain in the full suite.

Polyengine 0.6.7 reproduces `Trap: cannot leave component instance 0 (may_leave violation)` for `p2-echo こんにちは`, while an ASCII control exits normally. The normal `wasi:cli/exit` control signal is adapted separately and nonzero exits work; that integration issue was fixed before the final production tests. Unicode argv remains a mandatory failure. The host is shared; neither candidate substitutes its bundled WASI implementation.
